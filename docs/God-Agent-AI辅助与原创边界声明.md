# God-Agent AI 辅助与原创边界声明

> 最新证据快照：`113/113`；主测试 `736`，`735pass`、1 skip、0 fail；源码覆盖 `26146/28672 = 91.19%`，加载 `116/122`。

> 用途：考研复试现场说明 AI、开源资料、经典机制与个人工作的边界。  
> 本声明追求可核验，不以“AI 辅助”替代署名、许可证、测试或个人责任。

## 1. 建议现场表述

> 这个项目使用了 AI 工具辅助需求拆分、方案讨论、代码与测试草拟、文档润色和审计建议。AI 不是作者，也不承担项目责任。我负责确定研究问题和边界、选择或拒绝方案、复核实现、运行验收、保存负结果，并对最终提交和答辩表述负责。WAL、Lease、Fencing、Outbox 等是经典机制，不是我的原创发明；我的项目贡献是把它们映射到父子 Agent 的调用、Return、Proof 和 unknown 边界，并尝试用可复核实验验证。对于无法从记录可靠统计的“AI 生成代码比例”，我不会编造百分比。

## 2. 哪些属于公开知识或第三方基础

- WAL、Lease、Fencing Token、Outbox/Inbox、幂等消费者、CAS 等属于经典分布式系统与事务/消息机制；
- Agent Loop、图式编排、持久化执行、工具调用等属于行业公开概念；
- Node.js、Electron、TypeScript 及仓库依赖遵守各自许可证；
- 对 Codex、LangGraph、Temporal 等系统只能依据公开资料讨论；未完成同条件实验时，不得声称实现或性能优于它们；
- 直接复制或改编第三方代码、图表、文字时，必须按上游许可证保留来源、版权和 NOTICE 要求。

这些内容不能被表述为个人原创发明。更完整的引用规则见 `原创借鉴与引用说明.md`。

## 3. AI 的实际参与范围

AI 可能参与以下环节：

- 将自然语言需求拆成任务、测试条件和验收清单；
- 提供多种架构或 API 候选方案；
- 草拟、补全或重构部分代码和测试；
- 发现边界条件、生成反例和审计问题；
- 整理科研计划、答辩提纲、表格与文字；
- 辅助检查数字、路径、术语和 Claim 是否一致。

这意味着不应说“全部代码都由我从零手写”。若仓库没有完整、可信、逐行的生成记录，也不应反向声称某个精确 AI 占比。

## 4. 维护者必须承担的工作与责任

AI 输出进入项目之前，维护者仍需完成：

1. 明确问题、威胁模型、非目标和验收阈值；
2. 判断建议是否适合当前架构，并决定采纳、修改或拒绝；
3. 核对源码、测试、文档和实际运行结果是否一致；
4. 运行门禁，保留失败、`outcome_unknown`、blocked 和 NotVerified；
5. 检查敏感信息、安全风险、依赖许可证和引用；
6. 不把 Fake/Mock、计划、候选矩阵或本地 pilot 写成真实正式结果；
7. 对最终提交、论文文字、答辩陈述及其错误承担责任。

“AI 给出了答案”不能作为技术决策依据。最终解释必须能回到代码、测试、Raw、Manifest 或明确的未完成项。

## 5. 本项目可以主张的个人贡献

在有对应仓库证据和实际理解的前提下，可以表述为：

- 将 Agent 故障问题拆成 Model、Tool、Owner、Return、Proof 等提交边界；
- 组织稳定 Invocation ID、WAL、Lease/Fencing、Return Receipt、Snapshot CAS 和 `outcome_unknown` 的组合方案；
- 建立区分协议处理、业务完成、误完成和未知结果的指标口径；
- 建立测试发现、源码覆盖、故障注入、Raw/Manifest 和 Claim—Evidence 的审计流程；
- 对失败证据、能力边界和未完成实验作出最终判断。

以上是“设计、整合、验证和判断”层面的贡献，不应扩张为“发明了 WAL/Fencing”“证明了端到端 exactly-once”或“已经优于外部框架”。

## 6. 当前必须主动披露的证据边界

- test discovery 为 113/113；主测试共 736，其中 735 pass、1 个 Windows symlink 权限条件 skip、0 fail；不能把条件 skip 写成 pass，也不能换算成可靠性 95%；
- 当前正式 `src` 源码行覆盖为 26146/28672 = 91.19%，源文件加载率为 116/122 = 95.082%，coverage gate 为 90.25/93；加载率超过 95 不等于全仓行覆盖 95；
- GATE-40 为 candidate 40、local pilot 40 passed / 0 failed / 0 blocked、formal Verified 0、`complete=false`；Process Chaos 为 17/17；
- Provider 保持离线，`liveCalls=0`；
- Release Readiness 为 11/12、`BLOCKED`，官方审计 0 critical / 3 high，production 仍 `blocked`；
- 完整开发/构建依赖审计仍有 3 个 high；
- LangGraph、Temporal 等外部基线尚无同条件实测；
- 第三方无指导复现尚未完成；官方总账评分为 93/90/69/47/68，五项均未到 95。

因此不能让 AI 生成的流畅文字把这些限制改写成“95+”“生产级”“论文完成”或“已证明领先”。

## 7. 引用、相似性与许可证处理

- AI 给出的事实、代码模式和引用链接都需要人工核验；
- 改写、翻译或摘要第三方材料仍应标注来源，不能用 AI 改写规避署名；
- 发现与第三方代码或文字高度相似时，应追溯来源，按许可证保留声明，无法确认授权时移除或重写；
- AI 生成内容若包含疑似密钥、私有 URL、个人信息或受限数据，不得进入仓库和答辩材料；
- 依赖清单和许可证信息应以锁文件、SBOM 与上游许可证为准，AI 推断不能替代法务核验。

## 8. 复试追问的诚实回答

### “代码到底是不是你写的？”

> 项目使用了 AI 辅助，部分代码、测试和文档可能由 AI 草拟或共同迭代。我不把它说成完全手写。我承担的是需求定义、架构取舍、审查修改、执行验证和最终责任，并且我可以解释核心状态机、失败窗口和证据限制。

### “AI 做了这么多，你的能力体现在哪里？”

> 工程能力不只体现在敲代码，还体现在能否定义正确问题、识别 AI 建议中的错误、构造反例、建立验收门禁，并在证据不足时拒绝夸大。我的答辩重点是展示这些决策和验证过程；如果某部分我无法解释，就不把它算作自己的掌握。

### “如何证明不是抄袭？”

> 我会区分经典机制、公开资料、第三方代码和项目特定实现；直接引用或改编需要可追溯来源和许可证。AI 辅助不能自动证明原创，也不能免除引用义务。当前仓库有专门的原创、借鉴与引用说明，后续公开前仍需完成许可证与相似性核验。

## 9. 不得使用的表述

- “AI 只改了几个字”，除非有完整记录可以证明；
- “所有代码都是我独立手写”；
- “用了 AI，所以不需要引用来源”；
- “AI 已经验证没有漏洞、没有版权风险”；
- “经典机制的组合当然就是论文创新”；
- “测试通过说明 AI 生成内容一定正确”；
- “无法追溯来源，但看起来像通用代码，所以可以直接用”。
