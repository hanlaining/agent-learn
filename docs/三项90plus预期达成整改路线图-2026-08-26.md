## 三、科研证据闭环：69 → 90+

### 调整方向

从“本地离线验证”调整为“真实 Provider、正式 Raw、公开 baseline、独立复现、可审计 Artifact 链”。

### 必做调整

| 编号 | 调整 | 具体动作 | 交付物 | 验收标准 |
|---|---|---|---|---|
| A1 | 冻结 candidate | 固定 commit、环境、参数、种子、数据版本和配置 | candidate manifest、环境记录、配置 SHA | 所有结果绑定同一 candidate |
| A2 | 真实 Provider | 按预注册方案执行真实调用，记录成功、失败、重试、限流、超时 | 脱敏 receipt、模型版本、时间、调用计数 | `real Provider=1`，receipt 与 Raw 一一对应 |
| A3 | 正式 Raw | 原始输出只读归档，不用派生结果覆盖 | Raw、字节数、SHA-256、采样日志 | `formal Raw=Included` |
| A4 | 派生链 | 从 Raw 生成 derived、statistics、tables、figures | 每步命令、输入/输出 SHA、时间 | `Raw → derived → statistics → tables/figures → Claim` 可反查 |
| A5 | 外部 baseline | 使用公开数据/实现/论文基线，记录版本、许可、参数和资源 | baseline 来源、原始输出、运行日志 | `external baseline=1`，比较条件公平 |
| A6 | 独立复现 | 第二台机器、隔离环境或非作者执行同一流程 | 独立环境、命令、日志、差异解释 | `independent reproduction=1` |
| A7 | 统计审计 | 固定样本量、排除规则、置信区间、效应量、异常值和负结果 | 统计报告、失败样本、负结果索引 | 正文、图表、统计完全一致 |
| A8 | Claim 绑定 | 为每个 Claim 绑定 Evidence、Artifact、Locator、Reviewer、Status | Claim Matrix、限制和审阅记录 | 无孤立数字、无未来源 Claim |

验收命令：

```text

npm run test:reproducibility
npm run test:paper-evidence
npm run test:evidence
npm run evidence:verify
```

科研线只有在正式 Raw、真实 Provider receipt、外部 baseline、独立复现、失败/负结果和证据验证全部齐全后，才可复评为 90+。

## 六、执行顺序

### T+0：冻结边界

主控记录 candidate、环境和三项初始分数；禁止更新正式 Verified 状态。

### T+1：三线并行准备

- 科研：实验注册、Provider 采样表、Raw 目录、baseline 方案；
- 论文：Claim Matrix、方法清单、引用核验表、审阅预约；
- 发行：high 处置决策、签名环境、干净 Windows 测试清单。

### T+2：形成正式材料

- 科研：真实 Provider、正式 Raw、外部 baseline；
- 论文：从正式 Artifact 生成统计、图表和结果章节；
- 发行：签名包、SBOM、首次干净机安装。

### T+3：外部复核

- 科研：第二环境/非作者独立复现；
- 论文：非作者论文级审阅并关闭 P0/P1；
- 发行：升级失败、回滚、数据完整性和长稳。

### T+4：主控串行收口

1. 锁定正式 candidate 和全部 Artifact SHA；
2. 执行科研证据门禁；
3. 执行论文门禁和 `evidence:verify`；
4. 执行发行门禁和 `release:check`；
5. 全部通过后才更新评分和最终裁决。

| 外部/非作者人员 | 独立复现、论文审阅、发行复核 | 不得沿用原始执行者的自审结论 |

## 八、停止条件

出现以下任一情况，停止重复本地包装并标记 `RETURN_FOR_REWORK / NO-GO`：

- 正式 Provider、正式 Raw、外部 baseline 或独立复现缺失；
- Claim、Artifact、candidate、采样时间或 SHA 漂移；
- 论文仍含 TODO、NotVerified 或无来源数字；
- high/critical 未清零且无正式风险接受；
- 缺签名包、干净机、升级回滚或长稳 receipt；
- `evidence:verify` 或 `release:check` 失败；
- 同一阻塞连续两轮未减少或重复命令没有新增信息。
