# Codex 式快捷机制与个性化定义系统：完整实施计划

日期：2026-08-13  
项目：`D:\练手\agent-learn`  
状态：方案已记录，尚未实施  
文档目标：用一份可直接施工、逐阶段验收的计划，把 Codex 的快捷交互能力以 clean-room 方式复刻到 god-agent，并扩展为用户可自行定义的快捷能力平台。

## 0. 一句话结论

不要把本需求做成散落在 `App.tsx` 里的几个 `keydown` 判断。应建设一个同时服务 Electron 与 CLI 的“快捷能力内核”：

```text
用户输入
  ├─ 键盘快捷键
  ├─ / 斜杠命令
  ├─ @ 文件/上下文
  ├─ $ Skill
  ├─ ! 受控命令
  └─ 自定义快捷定义
        ↓
Shortcut Resolver（解析、补全、冲突处理）
        ↓
Command Registry（统一动作注册表）
        ↓
Policy Gate（权限、状态、作用域、安全校验）
        ↓
Action Dispatcher（本地 UI / Chat / Runtime / Tool / Skill）
        ↓
可观察结果（提示、执行记录、失败原因、撤销或恢复入口）
```

首版先做到“Codex 常用体验基本对齐”，再开放个性化定义；用户定义只能调用注册过的安全动作，不能绕过权限或把任意 Shell 暴露给 Renderer。

## 1. 需求解释与最终产品定位

本计划将“快捷机制”定义为六类能力，而不是只指键盘组合键：

| 能力 | 用户表面体验 | 底层本质 |
|---|---|---|
| 键盘快捷键 | `Ctrl+K`、`Ctrl+N`、`Ctrl+R` 等 | 一个按键组合触发一个稳定 Action ID |
| 斜杠命令 | 输入 `/model`、`/skills`、`/status` | 可搜索、可补全、带参数 Schema 的动作入口 |
| 上下文快捷引用 | 输入 `@文件`、`$skill` | 把明确的文件或 Skill 引用插入本次请求 |
| 会话快捷控制 | 运行中插话、排队、取消、恢复历史 | 根据 Turn 状态路由相同输入 |
| 受控执行快捷项 | 一键检查、测试、构建 | 固定 Command ID 到固定 argv，不接受任意 Shell 字符串 |
| 个性化定义 | 自定义键位、别名、提示模板、Skill 与工作流 | 分层配置 + 冲突检测 + 权限不扩张 |

产品定位：

> 这是 god-agent 的统一“意图快捷入口层”。它负责让高频动作更快到达，不负责重新实现 Agent Loop、Skill Loader、Tool Registry 或权限系统。

## 2. 官方能力基线与复刻边界

### 2.1 需要对齐的 Codex 体验

根据 OpenAI 官方文档，首轮基线至少覆盖：

- 输入 `/` 打开可搜索的斜杠命令弹层。
- `/model`、`/permissions`、`/status`、`/new`、`/skills`、`/plan`、`/review`、`/compact`、`/copy`、`/exit` 等常用入口。
- `/keymap` 式键位查看与重映射能力。
- 输入 `@` 搜索工作区文件并加入上下文。
- 输入 `$` 显式选择 Skill；保留模型按描述自动选择 Skill 的能力。
- `Up/Down` 恢复输入草稿历史，`Ctrl+R` 搜索输入历史。
- `Ctrl+O` 或 `/copy` 复制最近一次完整输出。
- Agent 工作时，`Tab` 将输入排入下一轮，`Enter` 将新指令注入当前 Turn；具体启用时要以本项目 Runtime 是否支持安全 steering 为前提。
- `Ctrl+C` 或 `/exit` 退出；运行中取消必须先结束挂起审批，防止取消竞态下 Tool 继续启动。
- 桌面侧常用全局入口：新建任务、搜索任务、打开命令面板。
- 个性化不只改键位：全局/项目指令、人格、Skill、常用工作流都属于长期个性化。

官方依据：

- [Codex CLI 与交互快捷机制](https://learn.chatgpt.com/docs/codex/cli)
- [Codex Developer commands 与 Slash commands](https://learn.chatgpt.com/docs/developer-commands?surface=cli)
- [个性化、Custom instructions 与 AGENTS.md](https://learn.chatgpt.com/docs/personalize)
- [Skills 与 Plugins](https://learn.chatgpt.com/docs/skills-and-plugins)
- [ChatGPT 桌面端](https://learn.chatgpt.com/docs/app)

### 2.2 “抄过来”的正确实现方式

本项目复刻公开行为、交互范式与能力合同，不复制 OpenAI 未公开源码、私有资产或内部实现。

允许：

- 按官方公开文档实现相同或相近的命令名、快捷交互和结果语义。
- 基于项目现有 App Server、Runtime、Skill Loader、Permission 与 Electron 架构重新实现。
- 在不破坏安全边界的前提下增加更强的用户自定义能力。

禁止：

- 猜测或伪造 Codex 私有协议。
- 为追求表面一致而绕过当前权限、沙箱或 IPC 白名单。
- 让自定义快捷项获得比用户当前会话更高的权限。
- 把所有 Codex 命令一次性做成空壳按钮。

## 3. 当前项目现状与差距

### 3.1 已有基础

| 已有能力 | 当前位置 | 可复用点 |
|---|---|---|
| CLI 基础斜杠命令 | `src/cli/main.ts` | 已有 `/help`、`/status`、`/threads`、`/new`、`/cancel`、`/exit` |
| 运行中输入路由 | `src/cli/input-router.ts` | 审批期间 `/cancel` 会先拒绝审批再取消 Turn |
| Electron 输入 | `src/electron/renderer/App.tsx` | Enter 发送、Shift+Enter 换行、Esc 关闭部分菜单 |
| Skill 发现 | `src/skills/skill-loader.ts` | 元数据目录 + `read_skill` 渐进披露 |
| Tool 注册 | `src/tools/tool-registry.ts` | 可以成为动作执行层的现有依赖 |
| 权限与 Sandbox | `src/permissions/`、`src/sandbox/` | 所有执行型快捷项必须复用 |
| App Server 与 Electron 桥 | `src/app-server/`、`src/electron/` | 统一命令 RPC 与安全 DTO 的落点 |
| 受控命令规划 | Electron 03 文档 | 已明确固定 Command ID → 固定 argv 的安全方向 |

### 3.2 核心缺口

- CLI 命令写在条件分支里，没有共享 Command Registry。
- Electron 没有 `/` 命令弹层，也无法复用 CLI 命令定义。
- 没有统一 Action ID，键位、菜单、斜杠命令可能各自实现同一逻辑。
- 没有快捷键冲突、平台差异、焦点上下文和禁用原因模型。
- 没有 `@` 文件、`$` Skill 的输入级补全器。
- 没有自定义别名、提示模板、参数变量和作用域配置。
- 没有“用户定义可以做什么、不可以做什么”的 Schema 与策略门。
- 没有快捷操作使用记录、失败原因、诊断页和回归测试矩阵。
- 现有 Skill 只能发现与读取，暂时缺少 UI 选择、明确注入和管理体验。

## 4. 产品原则

1. **一份动作，多种入口**：菜单、键位、斜杠命令、按钮只引用同一个 Action ID。
2. **状态决定可用性**：空闲、运行中、等待审批、离线、无工作区时，同一动作可见但状态不同。
3. **自定义不扩权**：快捷定义只是更快地表达用户意图，不是新的授权来源。
4. **本地优先**：个性化配置默认留在本机；项目共享配置必须显式选择且不得含机器秘密。
5. **渐进披露**：只展示匹配项；Skill 仍先注入元数据，命中后才读取正文。
6. **键盘优先但不排斥鼠标**：所有核心动作同时具备可点击入口、标签和可访问性说明。
7. **错误可解释**：冲突、参数错误、状态禁用、权限拒绝都返回用户可读原因。
8. **先最小闭环再扩张**：先做 12–15 个真实可用命令，不一次移植全部官方命令。

## 6. 个性化定义模型

### 6.1 支持的定义类型

| 类型 | 示例 | 是否调用模型 | 风险等级 |
|---|---|---:|---|
| `keybinding` | `Ctrl+Alt+T → panel.terminal` | 否 | 低 |
| `slash_alias` | `/ck → command.runPreset(check)` | 视目标而定 | 跟随目标 |
| `prompt_template` | `/修复 {issue}` 展开固定任务模板 | 是 | 中 |
| `skill_prompt` | `/日报 → $daily-brief + 模板` | 是 | 中 |
| `command_preset` | “完整检查”→ 固定 `npm run check` | 否 | 执行型 |
| `workflow` | 检查 → 测试 → 构建 → 汇总 | 部分 | 最高，后置实现 |
| `instruction_profile` | “中文、先计划、窄范围” | 是 | 中 |

### 6.2 建议配置合同

配置文件使用版本化、声明式格式。实现时可选 JSON 或 TOML；首选与现有 TypeScript 校验更直接的 JSON，UI 保存时原子写入。

```json
{
  "version": 1,
  "definitions": [
    {
      "id": "user.project.full-check",
      "label": "完整检查",
      "kind": "slash_alias",
      "trigger": "/full-check",
      "scope": "project",
      "targetAction": "command.runPreset",
      "arguments": { "presetId": "project.verify" },
      "when": ["runtime.connected", "turn.idle"],
      "enabled": true
    }
  ]
}
```

必须校验：

- `id` 唯一且带来源命名空间。
- `targetAction` 必须存在于 Registry 且允许被用户绑定。
- 参数严格符合目标 Action 的 Schema，拒绝额外字段。
- `scope` 只能是 `global | project | chat`。
- 自定义定义不能声明权限，只能继承目标 Action 的权限合同。
- `command_preset` 只能引用已预注册的 preset ID。
- 禁止配置任意 `cwd`、`env`、Shell 字符串、IPC channel、文件系统绝对写入目标。

### 6.3 配置分层与优先级

```text
系统内置默认
  < 用户全局定义
  < 当前项目定义
  < 当前 Chat 临时覆盖
```

同层冲突不静默覆盖，必须在保存时提示。跨层覆盖允许，但 UI 必须显示“覆盖了哪个定义”和一键恢复入口。

项目共享定义只保存可移植内容；以下字段禁止进入项目配置：

- Token、Cookie、密码、API Key。
- 用户主目录、临时路径、进程号、随机端口。
- 个人账号标识与机器专属工具路径。
- 未注册可执行文件和完整环境变量。

### 6.4 Prompt 模板变量

变量采用显式 Schema，不做无边界字符串替换：

```text
{{issue}}       必填文本，最多 2000 字
{{file}}        必须从工作区文件选择器产生
{{skill}}       必须从 Skill Catalog 选择
{{selection}}   只能来自当前编辑器/文件上下文
```

缺少必填变量时弹出小表单，不发送半成品。秘密变量不允许设置默认值，也不写入历史预览。

## 7. 统一架构设计

### 7.1 核心模块

```text
src/shortcuts/
├─ action-types.ts          # Action、上下文、结果、权限合同
├─ command-registry.ts      # 内置与可绑定动作注册表
├─ shortcut-resolver.ts     # 键位、/、@、$ 的解析与匹配
├─ shortcut-config.ts       # 分层配置读取、合并和版本迁移
├─ conflict-detector.ts     # 键位/命令/作用域冲突
├─ action-policy.ts         # 状态、权限、来源和参数校验
├─ action-dispatcher.ts     # 分发至 UI、Controller、App Server
├─ builtins.ts              # P0 内置动作定义
└─ command-presets.ts       # 固定 Command ID → 固定 argv
```

模块可按切片逐步建立，不要求首个 PR 一次生成全部文件。

### 7.2 Action 定义

```ts
interface ActionDefinition<TArgs = unknown> {
  id: string;
  label: string;
  description: string;
  category: "chat" | "composer" | "session" | "skill" | "context" | "workspace" | "app";
  argumentSchema: JsonSchema;
  defaultBindings: ShortcutBinding[];
  allowedSources: Array<"keyboard" | "slash" | "palette" | "button" | "user-definition">;
  availability(context: ActionContext): ActionAvailability;
  risk: "local-ui" | "read" | "write" | "execute" | "external" | "destructive";
  userBindable: boolean;
}
```

`availability` 返回 `enabled`、`hidden` 或 `disabled(reason)`。不要让 Renderer 自己猜测动作是否可执行。

### 7.3 Action 执行路径

| Action 类型 | 执行位置 | 示例 |
|---|---|---|
| 纯 UI | Renderer 内受控 handler | 打开搜索、关闭弹层、聚焦输入框 |
| Chat 状态 | Desktop Controller → App Server RPC | 新建、重命名、归档、恢复 |
| Runtime | App Server | 状态、取消、压缩、模型设置 |
| Skill | Skill Catalog / Runtime | 列表、显式选择、读取 |
| 受控命令 | Workspace Command Runner | 检查、测试、构建 |
| 外部副作用 | Tool + Permission | 以后按现有权限机制处理 |

Renderer 永远不能直接拿到 `child_process`、原始 argv、原始环境变量、任意文件系统 API 或任意 RPC method。

### 7.4 输入状态机

```text
Idle
 ├─ 输入普通文本 → Drafting
 ├─ 输入 /      → SlashPopup
 ├─ 输入 @      → FileMentionPopup
 ├─ 输入 $      → SkillPopup
 └─ 按全局键位 → ResolveAction

Popup
 ├─ Up/Down     → 移动选中项
 ├─ Enter/Tab   → 选中或补全
 ├─ Esc         → 只关闭弹层
 └─ 继续输入    → 过滤候选

TurnRunning
 ├─ Enter       → Steering（仅协议支持时）
 ├─ Tab         → QueueNextTurn
 ├─ Cancel      → DenyPendingPermission → turn/cancel
 └─ 禁用动作    → 显示原因，不静默失败
```

优先级：输入法组合态 > 系统保留键 > 打开的弹层 > 文本编辑 > Chat 动作 > 全局动作。

## 8. UI 与交互方案

### 8.1 命令面板

```text
┌────────────────────────────────────────────────────┐
│  > 搜索命令、快捷键或 Skill                  Esc  │
├────────────────────────────────────────────────────┤
│  会话                                              │
│  新建任务                         Ctrl+N    /new   │
│  查看状态                                  /status │
│                                                    │
│  设置                                              │
│  模型与推理                                /model  │
│  权限模式                            /permissions  │
│                                                    │
│  个性化                                            │
│  Skills                                     /skills│
│  快捷键                                    /keymap │
└────────────────────────────────────────────────────┘
```

要求：

- 模糊搜索命令名、说明、别名和快捷键。
- 显示当前键位、Slash 入口、来源和禁用原因。
- 高风险动作不因键盘选择而跳过确认。
- 最近使用只影响排序，不改变命令语义。
- 弹层打开后焦点进入搜索；关闭后焦点回到此前控件。

### 8.2 输入框内联弹层

- `/`：展示 Slash actions。
- `@`：只搜索已批准工作区内的文件/目录；首版不扫描忽略目录与敏感文件。
- `$`：展示 Skill 名称、说明、来源与启用状态。
- 弹层只在当前 token 位于触发上下文时出现；代码块、URL 和普通路径中的字符不能误触发。

### 8.3 快捷键设置页

包含：

- 搜索、按分类筛选、只看冲突、只看自定义。
- 显示默认键位、有效键位、来源层、适用上下文。
- 点击录制新组合键；检测系统保留键、重复键和输入法冲突。
- 恢复单项默认、恢复本层默认、导出本层配置。
- Windows 使用 `Ctrl`，macOS 展示 `Cmd`；定义层使用抽象修饰键 `Primary`。

### 8.4 自定义快捷项编辑器

首版采用表单，不开放代码编辑器：

1. 选择类型。
2. 设置名称与触发方式。
3. 选择允许绑定的目标 Action。
4. 填写由 Schema 生成的参数表单。
5. 选择全局/项目/Chat 作用域。
6. 查看权限与风险摘要。
7. 试运行解析，不产生外部副作用。
8. 保存并立即检测冲突。

## 9. 安全与权限合同

### 9.1 不可突破的边界

- 快捷键不是权限授权。
- 用户自定义定义不能新增 RPC method、IPC channel、Tool 或命令 argv。
- 运行型动作必须经过现有 Permission Gate 与 Workspace Sandbox。
- 删除、覆盖、凭据、系统级和外部发送动作仍按原规则确认。
- Renderer 只收到清洗后的动作 DTO，不收到函数、内部路径或原始配置对象。
- 配置解析失败时 fail-closed：忽略无效定义并显示诊断，不让 App 崩溃。
- 项目配置视为不可信输入；打开陌生项目时不自动启用执行型定义。

### 9.2 自定义执行快捷项

只允许：

```text
presetId = project.check
  → executable = npm
  → argv = ["run", "check"]
  → cwd = approvedWorkspaceRoot
```

不允许：

```text
command = "npm run check && 上传日志"
cwd = "C:\\"
env = { TOKEN: "..." }
```

固定 preset 也必须限制输出大小、执行时间、取消行为和敏感信息展示。

### 9.3 项目级定义信任

首次发现项目共享快捷定义时：

- 只读型、纯 UI 定义可以预览。
- 写入、执行、联网型定义默认禁用。
- 用户确认的是某个配置内容哈希；配置改变后重新确认。
- 不提供“永久信任此目录所有未来变更”的宽泛授权。

## 10. 分阶段实施计划

每一阶段都遵循：`分析 → 最小实现 → 自动验证 → 集成验收`。前一阶段未通过，不进入下一阶段。

### 阶段 A：行为清单与 Action Registry

目标：把已有能力抽象成统一动作，但不改变用户可见行为。

实施：

- 定义 Action ID、参数 Schema、来源、风险、可用状态和结果类型。
- 将现有 `/help`、`/status`、`/threads`、`/new`、`/cancel`、`/exit` 注册为 builtin actions。
- CLI 从 Registry 渲染帮助和路由命令；保留现有命令行为与输出兼容。
- 为 Electron 现有新建、搜索、模型、权限、发送、关闭菜单动作建立相同 Action ID。
- Registry 只存定义，不持有 UI 组件和进程对象。

预计修改：

- 新增 `src/shortcuts/action-types.ts`。
- 新增 `src/shortcuts/command-registry.ts`。
- 新增 `src/shortcuts/builtins.ts`。
- 修改 `src/cli/main.ts`，逐步移除命令条件链。
- 增加 `tests/command-registry-test.ts` 与 CLI 回归测试。

验收：

- 现有 CLI 命令全部保持可用。
- 重复 Action ID、无效 Schema、重复 Slash 名称启动时明确失败。
- `/help` 内容来自 Registry，不再手工维护第二份列表。

回滚点：只恢复 CLI 路由与删除新增 Registry，不触碰 Runtime、Skill 与 Electron UI。

### 阶段 B：Electron 命令面板与基础快捷键

目标：形成第一个完整的桌面快捷闭环。

实施：

- 增加命令面板组件、搜索、分类、键盘导航和禁用原因。
- 接入 `Ctrl+Shift+P`、`Ctrl+K`、`Ctrl+N`、`Ctrl+O`。
- 处理 Esc 优先级：先关最上层弹层，只有无弹层且明确绑定时才取消 Turn。
- 处理 textarea、select、dialog、输入法 composition 和系统菜单冲突。
- Preload 只暴露按 Action ID 调用的最小方法；Main/Controller 再映射到真实操作。

验收：

- 全键盘完成打开、搜索、选中、执行、关闭。
- 中文输入法组合过程中不误发送、不误触发。
- 离线或运行中动作显示准确禁用原因。
- 现有模型、权限菜单仍可用且与命令面板调用同一逻辑。

回滚点：移除命令面板与键位监听，不改变 App Server RPC。

### 阶段 C：`/`、`@`、`$` 输入解析与补全

目标：对齐 Codex 最核心的 composer 快捷入口。

实施：

- 实现 token-aware 输入解析器，不以简单 `startsWith` 代替。
- `/` 连接 Action Registry；支持模糊过滤、别名、参数提示。
- `@` 接入受控 Workspace 文件索引；返回安全相对路径与类型。
- `$` 接入 `SkillLoader.list()`；选择后保存结构化 Skill 引用。
- 消息 DTO 增加 `mentions` 与 `explicitSkills`，避免只靠拼接文本。
- App Server 校验引用仍属于当前工作区和当前 Skill Catalog。

验收：

- 输入 `/mo` 可定位 `/model`；选择后调用真实模型菜单/动作。
- `@` 不能引用工作区外路径、符号链接逃逸或敏感黑名单文件。
- `$` 选择 Skill 后，Runtime 能识别显式选择并按需读取正文。
- URL、代码片段和普通文字中的 `/ @ $` 不误开弹层。

回滚点：消息 DTO 保持向后兼容；关闭增强字段后普通文本发送仍正常。

### 阶段 D：键位系统与历史快捷交互

目标：建立跨平台、可测试、可重映射的 Keymap Engine。

实施：

- 统一键位正规化：`Primary`、`Alt`、`Shift`、`Key`。
- 增加上下文：global、composer、popup、timeline、sidebar、running-turn。
- 实现 Up/Down 草稿历史、Ctrl+R 历史搜索、Ctrl+O 复制。
- 支持双击 Esc 等序列键时，必须设置短超时与可取消状态；若可用性不稳定则不进入首版默认键位。
- 设置页展示默认值和有效值。

验收：

- Windows 与 macOS 映射单测完整。
- 同一组合键在不同上下文可合法复用；相同上下文冲突被阻止。
- 文本选择、中文输入、屏幕阅读器快捷键不被无条件劫持。

回滚点：保留内置默认键位，暂时关闭重映射入口。

### 阶段 E：个性化定义与分层配置

目标：让用户安全定义自己的快捷能力。

实施：

- 定义版本化 Schema、加载器、迁移器、分层合并与冲突诊断。
- 首版开放 `keybinding`、`slash_alias`、`prompt_template`、`skill_prompt`。
- 提供表单编辑、预览展开、试解析、启停、复制和恢复默认。
- 个人全局配置保存本机；项目配置仅显式选择才写入项目。
- 配置原子写入；保存失败不破坏最后一个有效版本。

验收：

- 用户可定义 `/日报`，选择指定 Skill 并展开带变量模板。
- 项目覆盖全局时 UI 明确显示来源和被覆盖项。
- 无效/旧版本配置得到迁移或诊断，不导致启动失败。
- 导出内容不含秘密和本机专属值。

回滚点：禁用自定义配置加载，继续使用内置动作与默认键位。

### 阶段 F：受控命令预设

目标：把“检查、测试、构建”等高频动作变成真正可靠的一键能力。

前置：Electron 03C 的 Workspace Command Runner 已完成并验收。

实施：

- 注册 `project.check`、`project.test`、`project.electronBuild` 等项目 preset。
- Registry 仅暴露 presetId、标签、预计耗时、风险和适用状态。
- 运行结果进入统一 Activity，并支持取消、输出限制和失败定位。
- 用户可给 preset 绑定键位或 Slash 别名，但不能修改 argv。

验收：

- Renderer 无法构造任意命令。
- 运行中、取消、超时、失败、成功状态完整。
- 输出过大或含敏感信息时经过限制和清洗。

回滚点：禁用 execution 类 Action，不影响其他快捷入口。

### 阶段 G：运行中 Steering、Queue 与工作流宏

目标：实现 Codex 式运行中插话/排队，并支持受限多动作串联。

前置：App Server 对 steering、queue、幂等、取消和顺序已有明确协议。

实施：

- Enter 只发送 steering；Tab 只进入 next-turn queue，两者 UI 明确区分。
- Slash 命令在运行中按各自策略立即执行、排队或禁用。
- 工作流宏只串联允许编排的 Action ID；每步重新做权限与状态校验。
- 失败策略仅支持 `stop | continue | ask`，首版不支持任意代码条件。

验收：

- steering 不创建重复 Turn，不丢消息。
- queue 顺序稳定，取消后状态可恢复。
- 宏不能借第一步授权覆盖后续步骤权限。

回滚点：关闭 steering 与 workflow feature flag，退回普通消息队列。

### 阶段 H：Skill 深度联动与能力沉淀

目标：让快捷系统不仅“快”，还能够持续加强专业能力。

实施：

- 快捷项可固定选择一个或多个互补 Skill，并显示执行顺序。
- 将“Chat Job 沉淀为 Skill”向导生成的 Skill 自动加入 Catalog 刷新流程。
- 可选生成对应 Slash 别名草稿，例如 Skill `daily-brief` 建议 `/daily`。
- Skill 更新后重新校验对应快捷定义，失效引用进入诊断而非静默调用旧内容。
- 记录 Skill 命中、用户显式选择、失败和手动纠正，用于人工迭代 Skill；不默认进行隐式自修改。

验收：

- 新安装 Skill 可立即或按明确重载规则被 `$` 与 `/skills` 发现。
- 删除/禁用 Skill 后，引用它的快捷项被安全禁用并说明原因。
- 快捷入口不复制 Skill 正文，仍遵循渐进披露。

## 12. 测试矩阵

### 12.1 单元测试

- Action ID 唯一、Schema 正确、默认键位合法。
- Slash 精确匹配、模糊匹配、别名、未知命令和参数错误。
- `@`、`$` token 边界与转义。
- 配置层级、覆盖、禁用、迁移和损坏恢复。
- 同上下文键位冲突与跨上下文合法复用。
- Windows/macOS 键位正规化。
- 运行中、离线、等待审批、无工作区的可用状态。
- 自定义定义无法绑定 `userBindable=false` 动作。
- command preset 拒绝额外参数、任意 cwd/env/argv。

### 12.2 集成测试

- CLI 与 Electron 读取同一 Registry，核心命令语义一致。
- Renderer Action DTO 经 Preload/Main/Controller 到 App Server 完整闭环。
- 切换 Chat 后快捷定义、草稿历史和显式 Skill 不串线。
- App 重启后全局/项目设置恢复，临时 Chat 设置按合同恢复或清除。
- 权限弹窗期间取消会先 deny，再取消 Turn。
- Skill 失效、文件被删、配置变更时安全降级。
- 固定命令取消后子进程树真正结束。

### 12.3 UI 验收

1. `Ctrl+Shift+P` 打开命令面板，输入“模型”找到并打开模型设置。
2. `Ctrl+K` 打开并聚焦任务搜索。
3. Composer 输入 `/`，用方向键选择 `/status`，Enter 执行。
4. 输入 `@`，只能找到当前工作区允许的文件。
5. 输入 `$`，选择 Skill，发送后 Runtime 明确记录为显式选择。
6. 中文输入法组合期间按 Enter 不误发送。
7. 弹层打开时 Esc 只关闭弹层，不取消 Turn。
8. 无弹层且 Turn 运行时执行取消，挂起审批先被拒绝。
9. 新建 `/日报` 模板，填写变量并发送，重启后仍存在。
10. 定义冲突键位，保存被阻止并指出冲突双方。
11. 禁用一个 Skill 后，对应快捷项显示失效原因。
12. 运行固定测试 preset，成功/失败/取消都在 Activity 中可追踪。

### 12.4 可访问性

- 命令面板、建议列表、键位录制器具备正确 ARIA role。
- 选中变化可被屏幕阅读器朗读。
- 状态不只靠颜色表达。
- 弹层焦点锁定、关闭后焦点恢复。
- 200% 缩放和窄窗口下不遮挡 Composer 主操作。

## 13. 性能与可观察性指标

目标指标：

- 打开命令面板到首屏可交互：本机冷启动后小于 100 ms。
- 本地候选过滤：P95 小于 16 ms。
- 键位响应不触发网络请求。
- `@` 文件索引增量更新，不在每次输入时递归扫描全项目。
- Skill Catalog 只加载名称与描述，正文按需读取。
- 配置保存使用临时文件 + 原子替换。

本地诊断事件：

```text
shortcut.resolved
shortcut.conflict
action.started
action.blocked
action.completed
action.failed
config.loaded
config.invalid
```

默认日志不记录完整 Prompt、文件正文、秘密参数或剪贴板内容。使用统计默认仅本地，用于排序时可关闭和清除。

## 14. 非目标

- 首版不实现任意 Shell 快捷键。
- 首版不一次覆盖官方全部 Slash commands。
- 不重新实现 Agent Loop、Tool Registry、Skill Loader 或 Permission Gate。
- 不把人格、AGENTS.md、Memory、Skill、快捷键混成一个无法解释的“大 Prompt”。
- 不允许模型自行永久改写用户快捷配置。
- 不在没有真实 Runtime 支持时伪造 `/plan`、`/compact`、steering 或 review 成功状态。
- 不把项目共享配置默认写入版本库；是否提交由用户另行决定。

## 15. 风险与对策

| 风险 | 对策 |
|---|---|
| JSX 内堆积大量快捷逻辑 | 从阶段 A 建共享 Registry，阶段 B 拆组件 |
| 键位与输入法/系统冲突 | composition 检测、上下文优先级、可重映射 |
| CLI 与 Electron 行为漂移 | 共享定义与契约测试；展示层可不同，Action 语义一致 |
| 自定义变成任意执行后门 | 只绑定注册 Action；参数 Schema；权限重新校验 |
| 命令很多但大多是空壳 | 只注册真实闭环；未实现能力不进入默认 Catalog |
| `@` 扫描过慢或泄露路径 | 增量索引、工作区边界、敏感黑名单、安全相对路径 |
| Skill 全文污染上下文 | 保持元数据目录 + `read_skill` 渐进披露 |
| 配置损坏导致无法启动 | 最后有效版本、原子写入、诊断后忽略无效条目 |
| 官方能力未来变化 | 内置动作带版本与 maturity，季度对照官方文档 |

## 17. 首版完成标准

以下全部满足，才称为“Codex 式快捷机制首版完成”：

- CLI 与 Electron 共享同一套核心 Action 定义。
- Electron 有可搜索、全键盘操作的命令面板。
- `/`、`@`、`$` 三种 Composer 快捷入口真实可用。
- P0 命令全部调用真实能力，没有空壳成功提示。
- 默认键位、状态优先级、输入法和弹层焦点行为稳定。
- 用户可以查看并修改键位，冲突可解释、可恢复。
- 用户可以创建至少四类安全自定义：键位、Slash 别名、Prompt 模板、Skill Prompt。
- 全局/项目/Chat 配置隔离正确，项目配置不会静默扩权。
- 受控执行只允许固定 preset，不能从 Renderer 传入任意命令。
- 单元、集成、Electron 构建与真实页面验收全部通过。
- 文档、设置页和 `/help` 都由真实 Registry 生成或校验，不出现三份不一致清单。

## 18. 推荐立即开始的第一刀

下一轮只实施阶段 A，不先画完整设置页，也不先添加几十个快捷键。

第一刀的最小目标：

```text
现有 CLI 六个命令
  → 注册为六个 Action
  → CLI 从 Registry 解析和生成 /help
  → 行为、输出与测试保持兼容
```

这样能先验证最重要的架构假设：同一动作能否脱离具体 UI，被 CLI 与未来 Electron 共同消费。阶段 A 稳定后，再进入命令面板和 `/ @ $`，返工风险最低。

## 19. 施工前需要确认的两个产品选择

1. **项目级自定义配置是否允许进入项目目录**：推荐允许，但默认仅本地保存；用户明确选择“共享到项目”时才生成项目配置文件。
2. **运行中 Enter 的语义**：推荐未来对齐 Codex 为“注入当前 Turn”，Tab 为“排到下一 Turn”；在真实 steering 协议完成前，继续沿用当前安全队列，不提前改变行为。

这两个选择不影响阶段 A–C 的核心架构，可在进入阶段 D/G 前最终确认。
