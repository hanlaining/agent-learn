# 04｜测试、视觉回归、可访问性与性能门禁

## 给负责人 Chat 的指令

建立测试与证据门禁，不替其他 Chat 修业务代码。发现问题时提交明确失败报告、复现步骤和归属切片。

## 状态

`DONE`；已新增 UI 质量门禁，覆盖文案、三栏边界、权限安全、浏览器拒权、未接入态和 Renderer 日志扫描。

## 允许修改路径

- `tests/electron/*`
- 新增 `tests/visual/*`、`tests/a11y/*`、`tests/e2e/*`
- 新增测试 fixture、截图 manifest 和报告脚本
- 测试配置仅允许增加门禁，不得改变运行环境或放宽阈值

## 禁止修改路径

- 生产组件、Runtime、权限策略和数据语义（除非主控 Chat 明确分配修复）
- 视觉基线图片（只能由 QA 重新生成并记录原因）
- env、auth、token、lockfile、构建缓存

## 必测矩阵

| 维度 | 必测内容 | 阻断条件 |
|---|---|---|
| 启动 | 冷/热启动、空数据、损坏缓存、离线 | 白屏、崩溃、未捕获异常 |
| 三栏 | 默认、窄屏、超宽、分隔器边界 | 重叠、裁切、横向滚动 |
| 状态 | idle/loading/running/success/error/cancel/retry/unavailable | 伪成功、状态倒退、按钮误启用 |
| 安全 | 权限、危险 URL、未审批命令、敏感文案 | 任何未审批副作用或泄漏 |
| 幂等 | 重复发送、retry、approve、导航、列表加载 | 重复消息、重复执行、重复事件 |
| 恢复 | 断网、重启、晚到事件、服务端最终状态 | 自动放行、状态回滚、数据丢失 |
| 视觉 | 12 个 1024×1024 SCREEN STATE | 关键区域超阈值或文字变化 |
| a11y | 键盘、焦点、ARIA、对比度、减少动画 | 高危/严重项、焦点丢失 |
| 性能 | 首屏、长列表、20 Agent、30 分钟稳定性 | 超时、明显卡顿、持续内存增长 |

## 视觉回归规则

- 固定 viewport、DPR=1、locale、timezone、字体和等待条件。
- 12 个基线命名为 `screen-01` 至 `screen-12`，动态时间、随机 ID 和进度必须固定或 mask。
- 全图像素差 ≤0.5%，关键区域差异 ≤0.1%，SSIM ≥0.98；文字区域不得新增/缺失字符。
- 任一超阈值都必须人工复核；没有复核记录不得放宽阈值。

## 核心 E2E 路径

1. 冷启动 → 新建任务 → 输入 → Enter 发送 → Runtime running → completed。
2. 发送中取消 → failed → retry；只生成一个新 attempt。
3. read 权限允许一次；第二次必须重新审批。
4. sensitive 权限拒绝；无任何副作用。
5. 搜索有结果/无结果/清空；选中态和分组恢复。
6. 切换五个 Inspector tab；内容、滚动和筛选不串线。
7. 浏览器输入危险 URL；被拒绝后可恢复到本地预览。
8. 多 Agent 一项失败；主线程局部重试，不重复已完成节点。
9. 部署成功；复制预览链接；返回线程后证据摘要仍存在。
