# GodAgent 小清新高保真 UI 重做总计划

## 任务标题

GodAgent Electron 桌面端：三栏工作区与 12 个 SCREEN STATE 的简约小清新重做。

## 目标

在不改变 Runtime、权限、工具和持久化语义的前提下，把现有桌面端统一为浅色、留白、薄荷绿、柔和珊瑚的生产级 UI，并让 12 个屏幕状态可启动、可交互、可回归验证。

“禁止出错”在本计划中定义为：不允许 P0/P1 缺陷、未捕获异常、敏感信息泄漏、重复副作用、视觉门禁失败或未解释的测试失败。不能用“基本可用”替代 PASS。

## 当前已知边界

- GodAgent 当前是本地单机研究原型，不把 UI 重做宣传为生产级多租户能力。
- 变更检查、任意桌面终端、正式安装发布和多机 Runtime 当前未完成；UI 必须诚实显示未接入态，不伪造功能。
- 真实模型、终端、部署和外部浏览器在 UI 开发阶段全部使用 deterministic mock，不产生真实副作用。
- 当前 worktree 有大量既有未提交改动，本计划只允许各 Chat 修改自己声明的路径；不得重置、回滚或覆盖他人改动。

## 共享契约（先冻结，后并行）

- UI 状态：`idle | loading | running | awaiting_permission | completed | failed | cancelled | retrying | unavailable`。
- Runtime 事件：`eventId` 唯一，包含 `parentId`、`agent`、`kind`、`startedAt`、`endedAt`、`status`、`detail`、`errorCode`。
- 权限请求：`requestId` 唯一，包含 `risk=read|execute|sensitive`；“允许一次”只对当前 request 生效。
- 所有重试、导航、列表加载和权限提交必须带幂等标识；UI 以最终状态为准，不以乐观状态覆盖失败。
- 真实未接入能力只能显示明确空态：“变更检查尚未接入”“桌面终端尚未接入”。

## Chat 执行规则

1. 每个 Chat 开始前先读取本仓库 README、相关源码和本需求 MD。
2. 只修改“允许修改路径”；发现跨域问题时写阻塞说明，不直接改他人文件。
3. 不新增依赖，不改变 API 语义，不执行真实模型、终端、部署或外部网络副作用。
4. 每次交付必须回传：变更摘要、测试命令与通过数、截图证据、已知风险、下一依赖。
5. 没有测试证据、截图证据或明确 BLOCKED 原因，视为未完成。

## 统一测试门禁

- 构建/类型/lint：全部通过，零未解释 warning。
- 单元/集成/E2E：所有正向、反向、幂等、恢复、断网、重启、取消、重试用例通过。
- Electron：冷启动、热启动、空数据、损坏缓存和离线启动不得白屏或崩溃。
- 视觉：12 个状态固定 1024×1024 基线；关键区域差异超阈值即阻断。
- 可访问性：键盘全流程、焦点陷阱、ARIA、非颜色状态、WCAG AA。
- 安全：无 token、绝对路径、堆栈或敏感参数泄漏；危险 URL 和未审批命令必须拒绝。
- 性能：首屏可交互 ≤3 秒；1000 条历史、200 个 Timeline 节点和 20 个 Agent 不出现明显卡顿。

## 合并顺序

`01 Shell/Token → 02 Conversation/Runtime + 03 Inspector/Permission/Browser → 04 QA → 05 Integration/Release`。

任一阶段出现 P0/P1、未捕获异常、重复副作用、视觉门禁失败、构建失败或未解释 warning，状态必须为 `BLOCKED`，不得继续发布。

## 完成定义

- 12/12 状态可稳定渲染，文字和状态准确。
- P0/P1 = 0；P2 只有在有负责人、截止日期和明确不影响主流程的情况下才能延期。
- 全量测试报告、截图基线、环境信息和 commit 可追溯。
- 两名独立复核者完成人工走查；任何一项未完成都不能标记 PASS。
