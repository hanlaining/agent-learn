# God-Agent 智囊团：生产发布与安全评审

> 审查日期：2026-08-24  
> 角色：生产发布、安全与运维独立评审  
> 结论：**68/100，No-Go；可称 local-ready，不可称 production-ready。**

## 1. 客观结论

当前仓库已经具备较完整的本地门禁、离线 Demo、Runtime Doctor、SBOM、操作手册和故障语义，`Release Readiness` 为 `local-ready 11/11`。这足以支持本机演示和工程研究原型交付，但不能外推为生产发行成熟。

生产放行仍被以下事实阻断：

- production 状态明确为 `blocked`；
- Provider 证据仍为 offline，`liveCalls=0`；
- 完整开发/构建依赖审计仍有 3 个 high；
- 缺签名安装器、卸载验证、升级与回滚闭环；
- 缺真实 Provider 的重试、取消、状态查询、限流与预算验证；
- 缺长浸泡、资源泄漏、恢复积压和断电语义证据；
- 缺干净机器安装到启动的独立验收。

## 2. 分项判断

| 分项 | 判断 | 主要证据或缺口 |
|---|---|---|
| 本地发布门禁 | 较强 | `local-ready 11/11`，但仅覆盖仓库定义的本地检查 |
| 安装与版本生命周期 | 不足 | 无签名发行物、升级迁移和回滚验收 |
| 运维与可观测性 | 中等 | 有 Doctor、结构化资料和 Runbook，缺生产 Crash/Metric/Trace 闭环 |
| 持久化与恢复 | 中上 | WAL、Lease/Fencing、Receipt、Process Chaos 证据较强；缺断电、损坏、备份恢复与长稳 |
| Provider 生产能力 | 明显不足 | `liveCalls=0`，不能验证真实幂等、状态查询、取消和限流 |
| 安全与供应链 | 未闭环 | runtime-only 审计为 0，但完整依赖审计仍有 3 high；签名、秘密管理和供应链放行未闭环 |
| 干净机器与支持范围 | 不足 | 尚无独立干净 Windows 安装、卸载、升级、恢复和支持边界验收 |

## 3. 达到 95 分的必要条件

以下条件必须同时满足，不能靠修改评分文字替代：

1. 解决完整依赖审计 3 个 high，完成全量回归、重新审计和 SBOM 更新。
2. 生成可安装、可卸载、可校验的签名发行物，验证升级、配置迁移和回滚。
3. 在明确预算和授权下接入真实 Provider，验证重试、取消、状态查询、限流、预算与故障语义。
4. 完成持久层容量、损坏恢复、备份恢复、断电和恢复积压试验。
5. 完成短浸泡和长浸泡，并给出 CPU、内存、句柄、磁盘、积压和恢复时间报告。
6. 在干净 Windows 环境由第二执行者完成安装、启动、核心任务、故障恢复、升级、卸载验收。
7. 冻结 Release Notes、已知限制、支持范围、故障手册、制品哈希、SBOM 和许可证清单。

## 4. 持续精进顺序

| 优先级 | 实施切片 | 完成定义 |
|---|---|---|
| P0 | 供应链与事实门禁 | 3 high 清零或有正式风险接受；README/发布报告数字由机器校验，事实漂移能使门禁失败 |
| P0 | 安装生命周期 | 签名候选包在干净机器完成安装、升级、回滚、卸载 |
| P1 | Provider 受控实调 | 固定模型、预算、调用上限和数据边界；输出 Raw、日志和费用记录 |
| P1 | 持久化灾难恢复 | 损坏、备份、恢复、断电和积压场景全部有可重放证据 |
| P1 | 浸泡与资源 | 8 小时短浸泡和 24 小时长浸泡无 P0/P1 泄漏或不可恢复积压 |
| P2 | 外部发行验收 | 第二执行者按手册复现，制品哈希、SBOM、许可证和 Release Notes 一致 |
