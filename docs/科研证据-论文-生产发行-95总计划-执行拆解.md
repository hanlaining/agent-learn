```text
formalVerified=0

```

文档、评分、Mock/Fake、Draft、local pilot、Electron ready、Doctor READY、离线 Provider、同作者同机器复跑，均不能替代真实 Provider、正式 Raw、外部 baseline、独立复现、非作者审阅或生产证据。不得修改依赖、`package-lock.json`、覆盖分母/阈值、`current-evidence.json` 或 Verified 状态来规避门禁。

## 3. 并行小需求与文件白名单

### A — 工程真实行为覆盖

范围：`src/runtime/lifecycle.ts`、`src/app-server/main.ts`、`src/app-server/handlers.ts`、`src/agent/agent-loop.ts` 及对应 `tests/`。

补齐启动/关闭、非法输入、超时、取消、Provider 错误、重试、lease 获取/续租/过期/释放、子进程退出、恢复、重复调用和并发幂等。每个切片必须有正向、反向、边界、恢复/幂等用例，不得空 import。

验收：专项测试 → `npm run check` → `npm run test:discovery` → `npm test` → 两次独占 `npm run test:coverage`。

### B — 正式 Provider 与 Raw 证据协议

范围：`research/reproducibility/`、`docs/evidence/`、对应校验器和测试；不得伪造正式 Raw。

定义 Provider receipt、Raw→derived→statistics→table/figure→manuscript SHA 链、候选版本、采样时间、资源约束、失败/负结果和 manifest。缺字段、Mock/Fake Provider、时间漂移、SHA 漂移、路径越界必须 fail-closed。真实授权只检查变量名存在性，不读取或输出密钥值。

### C — 外部 baseline 与独立复现

范围：`research/` 复现 runbook、baseline schema、receipt 和测试。

外部 baseline 必须有公开数据/许可、明确 comparator、版本、同等资源约束、原始输出和差异解释。独立复现必须由第二机器、非作者执行者或独立隔离环境完成，并保留独立环境摘要、输出 SHA 和 receipt；同作者同机器复跑只能标记 local pilot。

### D — 论文 Claim、引用与表图一致性

范围：`research/paper/`、论文校验脚本和测试。

建立 `Claim → Evidence → Artifact → Locator → Reviewer → Status`。检查正文/表格/图/README 旧数字漂移、引用一手来源和定位、候选 SHA、未验证 Claim 越权。正式结果不足时保持 `NotVerified/TODO` 和 `publication review=NotReviewed`。

### E — 发行、安全与恢复证据

范围：`scripts/release-*`、`scripts/security-*`、`tests/release-*`、发行协议文档。

处理官方审计 3 个 high（修复或正式风险接受），验证签名包、构建 SHA、SBOM、安全扫描、干净 Windows 安装、Electron main/App Server/Renderer 联通、升级、失败回滚、配置迁移、长稳和崩溃恢复。缺任一原始外部 receipt，`release:check` 必须 BLOCKED。

### F — 非作者论文/发行复核

范围：审阅清单和候选 manifest；不得由实现者自审充数。

记录审阅者身份、时间、逐条意见、修订前后差异、未解决风险和结论。无独立审阅时保持 `NotReviewed`。

每个核心行为至少覆盖：正常、非法/缺字段、边界、外部失败、超时/取消、重试、重复调用、恢复。主控每个切片串行运行：


## 6. 90% 与 95% 放行条件

### 90%

- 工程真实行为覆盖和全套门禁通过；
- 正式 Raw、真实 Provider、外部 baseline、独立复现均有原始证据；
- 主要 Claim 与 Artifact、引用、图表一致；
- high 风险有修复或正式风险接受；签名包、干净机安装、升级回滚和一次长稳完成；
- 至少一次非作者论文/发行复核。

### 95%

- 上述条件全部满足；
- 第二次独立复现、第二台干净机、独立执行者、第二次长稳完成；
- 负结果、限制、威胁有效性完整；
- Raw、统计、论文、发行包 manifest/SHA 同一候选；
- 连续两次全套门禁通过、无 evidence drift、无未处理 high。

## 7. 返工与禁止放行规则

任一测试失败、覆盖低于 95%、分母变化、候选/时间漂移、证据缺失、越界修改或状态冒充，立即标记：

```text
RETURN_FOR_REWORK / NO-GO
```

在连续两次独占 coverage ≥95% 且全部门禁和外部证据齐全前，不得更新 `current-evidence.json`、最终裁决或 Claim 的 `Verified` 状态，不得 commit、push、创建或合并 PR。
