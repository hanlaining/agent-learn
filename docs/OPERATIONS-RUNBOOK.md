# God-Agent 运维与故障处置手册

> 适用范围：当前 Windows / Node 20 源码构建与内部验证环境。安装器、自动升级、已签名生产包、完整灾备和真实 Provider 尚未验收，本手册不能被当作生产 SLA 证明。

## 1. 运行边界与状态位置

默认用户状态位于：

```text
%LOCALAPPDATA%\god-agent\runtime-state.json
%LOCALAPPDATA%\god-agent\runtime-leases.json
%LOCALAPPDATA%\god-agent\outcome-unknown-resolutions.json
```

若未设置 `LOCALAPPDATA`，代码会回退到用户目录下的 `.local/share/god-agent`。`AGENT_STATE_PATH` 可覆盖 Runtime 状态路径，`AGENT_OUTCOME_UNKNOWN_STATE_PATH` 可覆盖不确定结果记录路径。覆盖路径属于本机敏感配置，不应提交仓库。

Provider 相关变量名为 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`。Key 只能从进程环境注入，禁止写入脚本、命令历史、工单、截图或日志。

## 2. 启动前检查

```powershell
npx --no-install tsx scripts/runtime-doctor.ts
```

只有输出 `READY` 且所有硬检查为 `PASS` 才进入下一步。常见判断：

| 检查 | 含义 | 处置 |
| --- | --- | --- |
| `node` 失败 | 不在 Node 20 已验证范围 | 切换到 Node 20，不以“更新版本应兼容”放行 |
| `platform` 失败 | 不是当前支持的 Windows `win32` | 停止启动，转入兼容性验证 |
| `files` / `dependencies` 失败 | 发布文件或本地依赖不完整 | 核对候选校验值；在源码环境用锁定安装恢复 |
| `build` 失败 | Electron 主进程或渲染产物缺失 | 对冻结候选重新执行 Electron 构建与全门禁 |
| `temp-write-cleanup` 失败 | 临时目录不可写或清理异常 | 检查磁盘、权限、安全软件和临时目录配额 |
| `provider` 警告 | 可离线启动，但真实对话不可用 | 不得将离线状态报告为 Provider 可用 |

doctor 的 Provider 检查只枚举变量名，不读取或打印值。它不能验证凭据正确、额度充足或网络可达。

## 3. 启动、停止和健康判断

源码环境构建与启动：

```powershell
npm run electron:build
npm run electron:dev
```

健康判断至少包括：

1. doctor 硬检查通过；
2. App Server 进入 ready，Electron 窗口可以连接；
3. 无 Provider 时界面明确禁用 `turn/run`，不能把窗口打开视为核心链路可用；
4. 有 Provider 时必须另行完成受控真实冒烟，不能只依据变量名存在判断；
5. 状态文件持续可写，且没有租约冲突或不确定结果被静默吞掉。

停止时优先正常关闭 Electron 和 App Server，等待状态写入完成。只有进程无响应时才强制终止；强制终止后必须按第 6 节执行恢复检查。

## 4. 事件分级

| 等级 | 示例 | 首要动作 |
| --- | --- | --- |
| P0 | 状态丢失/损坏、重复外部副作用、凭据泄漏、无法安全回滚 | 停止相关进程与发布，隔离凭据，保全证据，通知负责人 |
| P1 | 全部用户无法启动、任务持续卡死、Provider 大面积不可用 | 停止扩大影响，记录候选 SHA/环境，切离线或回退到已验证版本 |
| P2 | 单任务失败、性能明显下降、局部功能不可用 | 保存任务关联信息与脱敏日志，按故障表定位 |
| P3 | 文案、非关键展示或有规避方式的问题 | 建单并排期，不绕过发布门禁 |

任何事件都记录：发生时间、候选 SHA/版本、Node/Windows 版本、是否真实 Provider、操作序列、影响范围、原始错误、处置人和最终结论。不得只保留复跑成功记录。

## 5. 常见故障处置

| 症状 | 可能原因 | 安全处置 |
| --- | --- | --- |
| Electron 窗口打开但不能对话 | 未配置 Key，或 App Server 未连接 | 查看 UI/App Server 明确信息；先跑 doctor；不要反复提交相同请求 |
| Provider 401/403 | Key、账号或目标环境不匹配 | 停止重试；在安全渠道核对变量来源和权限，日志中不得粘贴 Key |
| Provider 408/429/5xx | 网络、限流或服务异常 | 保留请求关联信息；遵守有上限退避，超过预算/次数立即停止 |
| 请求结果不确定 | 响应丢失、进程在提交后崩溃 | 不自动重放可能有副作用的操作；进入 Unknown Outcome 人工确认流程 |
| Lease 冲突或任务长时间不推进 | 并发进程、旧租约或时钟/状态异常 | 确认是否仍有活进程；保全 state/lease 文件后再处理，禁止直接删 Lease 解锁 |
| 状态 JSON 无法读取 | 磁盘中断、写入损坏或人工修改 | 立即停进程，复制原文件和目录元数据；从已验证备份恢复，禁止原地修 JSON |
| 磁盘持续增长 | 状态、报告或日志积累 | 确认增长来源和保留要求；先归档再清理，禁止批量删除未知状态 |
| 临时目录检查失败 | 权限、磁盘不足、安全软件拦截 | 释放空间或修复权限后重跑 doctor；不得忽略失败继续运行 |

## 6. 崩溃与状态恢复

1. 停止 Electron 与 App Server，确认没有进程继续写状态。
2. 复制整个 `god-agent` 状态目录到带时间戳的只读证据目录；记录文件大小和 SHA-256。
3. 保留 `runtime-state.json`、`runtime-leases.json`、`outcome-unknown-resolutions.json` 的原件，不原地修改、不手工删除 Lease。
4. 记录崩溃前最后一个用户动作、是否涉及外部副作用、是否收到 Provider 响应。
5. 在副本或隔离环境运行相同版本的恢复验证；若结果属于 Unknown Outcome，先人工查证外部系统，再决定是否重试。
6. 只有已有同版本、同状态格式且校验通过的备份时才恢复。恢复前再次备份当前损坏状态。
7. 恢复后先做只读检查和离线测试，再允许真实 Provider 或有副作用工具运行。

当前没有经安装器验证的一键恢复功能。无法证明备份兼容时，应保持停机并升级为 P0/P1，不能试错覆盖唯一状态。

## 7. 备份、升级与回滚

### 升级前

- 停止所有 God-Agent 进程。
- 备份第 1 节列出的三个状态文件及其父目录元数据。
- 记录旧版本、新版本、源码/安装器 SHA-256 和状态 Schema 版本。
- 在隔离副本演练升级；没有演练成功证据不得覆盖现用环境。

### 回滚触发条件

- 新版本无法启动或 doctor 硬门禁失败；
- 状态迁移失败、数据丢失或出现重复副作用；
- P0/P1 故障且在预定窗口内无法止损；
- 签名、校验、SBOM 或依赖来源不匹配。

### 回滚原则

停止新版本，保全故障状态，核验旧版本安装介质与校验值，再恢复与旧版本兼容的升级前备份。不得让旧版本直接打开已被新版本不可逆迁移的唯一状态副本。

**当前限制：**安装器、自动升级、状态迁移兼容矩阵和完整 `N -> N+1 -> N` 演练尚未完成，因此实际生产回滚能力为未验证。

## 8. Provider 安全与费用止损

- 默认使用离线轨道。真实冒烟必须获得账号、费用和数据处理授权，并遵守 `docs/provider-capability-smoke.md`。
- 设置请求次数、单次费用、总费用和超时硬上限；达到任一上限立即停止。
- `AbortSignal` 只表示本地传输取消，除非 Provider 明确确认，否则不能宣称服务端任务已取消。
- 不确定结果不得盲目重试；先查 Provider 侧请求状态或人工确认外部副作用。
- 对外分享前对 Authorization、Key、用户内容、绝对本机路径和 Provider 原始响应做脱敏；原始证据进入受控存储。
- 怀疑凭据泄漏时立即停用/轮换凭据、停止相关任务并按 P0 处置，不能只删除日志。

## 9. 发布后观察与退出标准

发布观察窗口内持续记录启动成功率、任务成功/失败/Unknown Outcome、恢复次数、Provider 错误、内存/磁盘增长和用户影响。满足以下任一条件应停止扩大部署：

- 出现状态损坏、重复副作用、凭据泄漏或无法解释的数据丢失；
- 错误率、资源增长或恢复时间超过预注册阈值；
- 安装器签名或构建校验不一致；
- 无法在既定窗口内完成安全回滚。

目前长稳阈值、生产 SLO、值班体系和真实发布观察数据均未建立。补齐并演练前，不得把本手册描述为成熟生产运维体系。
