# god-agent 托管联网搜索与引用展示实施计划

日期：2026-08-03

## 1. 目标

让当前单 Agent Runtime 在不引入 MCP、Browser Bridge 或本地浏览器抓取的前提下，完整支持 Responses API 托管 `web_search`：

1. 模型可按需选择真实联网搜索。
2. CLI 能展示搜索开始、查询内容和完成状态。
3. CLI 能展示 Provider 返回的公开 URL 引用。
4. 搜索过程中仍能展示公开 Reasoning Summary SSE。

金融金额继续由确定性 Tool 计算；网页搜索只负责查询公开资料，不能替代金额计算。

## 2. 架构边界

```text
用户问题
  -> Agent Loop
  -> Responses Provider
       |-- function Tool：Runtime 本地执行，经过 Registry/Permission
       `-- web_search：Provider 托管执行，不进入本地 Tool Registry
  -> Summary SSE + Web Search SSE + Citation SSE + Assistant SSE
  -> Agent Event System
  -> CLI
```

`web_search` 是 Provider 托管 Tool。模型服务完成联网、抓取和结果注入，Runtime 不执行任意 URL 请求，因此不扩大当前 Workspace Sandbox 的网络权限。

## 3. 已完成的能力探测

使用当前 LovBrowser Responses 端点和 `gpt-5.6-sol` 发送脱敏探针，请求包含：

```json
{
  "tools": [
    {
      "type": "web_search",
      "external_web_access": true,
      "search_context_size": "low"
    }
  ]
}
```

真实返回 HTTP 200，并出现：

```text
response.web_search_call.in_progress
response.web_search_call.searching
response.web_search_call.completed
response.reasoning_summary_part.added
response.reasoning_summary_text.delta
response.output_text.annotation.added
response.output_text.delta
response.completed
```

结论：当前 Provider 原生支持托管联网搜索、公开推理摘要和文本引用，不需要额外 Bridge。

## 4. 实施切片

### 切片 1：托管搜索请求

目标：让 god-agent 发出的 Responses 请求默认声明 `web_search`。

修改：

- `src/llm/openai-responses.ts`
  - 增加 Web Search 配置类型。
  - 把托管 Tool 与现有 function Tool 合并进请求体。
- `src/app-server/main.ts`
  - 显式启用 live Web Search。
- `tests/openai-responses-test.ts`
  - 断言请求体同时包含 function Tool 和 `web_search`。

验证：Provider 单测、`npm run check`、真实 HTTP 探针。

回滚点：删除 Provider 的 Web Search 配置和一个托管 Tool，不影响本地 Tool。

### 切片 2：搜索生命周期事件

目标：从 SSE 到 CLI 展示搜索状态。

修改：

- `src/llm/types.ts`
  - 增加 `web_search_started`、`web_search_searching`、`web_search_completed`。
- `src/llm/openai-responses.ts`
  - 解析 `response.output_item.added/done` 和 `response.web_search_call.*`。
- `src/agent/agent-loop.ts`
  - 转发 Provider 搜索事件。
- `src/agent/events.ts`
  - 增加公开 `web_search/*` Event 并校验。
- `src/cli/main.ts`
  - 普通模式显示 Search 状态，debug 模式保留内部字段。

验证：Provider、Agent Event、Agent Loop、CLI Smoke Test。

回滚点：删除新增联合类型和对应分支，不影响 Assistant/Reasoning 事件。

### 切片 3：URL 引用

目标：展示 Provider 真实返回的来源，禁止模型伪造 Sources。

修改：

- `src/llm/types.ts`
  - 增加 URL Citation 事件。
- `src/llm/openai-responses.ts`
  - 只接受结构合法的 `url_citation` annotation。
- `src/agent/agent-loop.ts`、`src/agent/events.ts`
  - 转发和校验引用事件。
- `src/cli/main.ts`
  - 去重并在 Assistant 输出结束后显示 Sources。

验证：Mock 引用、重复引用、非法 URL、事件顺序和真实 CLI。

回滚点：删除引用累计和 Sources 渲染，不影响正文输出。

## 6. 安全约束

- 不读取、记录或输出 Key、Cookie、Authorization。
- 不展示 `reasoning.encrypted_content` 或隐藏思维链。
- 只展示 Provider 公开 Summary。
- URL 引用必须来自 Provider annotation，并限制为 `http:` 或 `https:`。
- 不把网页中的数字直接当成金融确定性结果。
- 不修改 Git 分支、Worktree，不提交、不推送。

## 8. 实施记录

### 2026-08-03：三个切片全部完成

切片 1：

- `OpenAiResponsesProvider` 支持配置托管 `web_search`。
- App Server 默认声明 live Web Search，搜索上下文为 `low`。
- function Tool 与托管 Tool 在同一个 Responses 请求中并存，但执行边界保持分离。
- 新增请求级 `allowHostedTools`；Context Compactor 显式设为 `false`，保证内部压缩不会联网或调用 Tool。

切片 2：

- Provider 解析搜索开始、搜索中和完成事件。
- 搜索 `callId`、最终查询文本贯穿 LLM Event、Agent Loop 和 Agent Event System。
- CLI 普通模式显示 `Search ›`、`Search ✓`，debug 模式保留 callId 日志。
- 同一搜索的重复状态事件不会重复发出生命周期节点。

切片 3：

- Provider 解析 `response.output_text.annotation.added` 中的 `url_citation`。
- 只接受合法的 `http:`、`https:` URL 和合法文本索引。
- 引用通过 Agent Event System 到达 CLI，不从 Assistant 普通文本猜测来源。
- CLI 按 URL 去重，并在 Assistant 流结束后显示 `Sources:`。
