# God-Agent 通用模型插座

完整的阶段拆解、逐条测试步骤、预期结果和交付门禁见[《God-Agent 通用模型插座：实施与详细测试计划》](./God-Agent-通用模型插座-实施与详细测试计划.md)。

## 目标

God 的 Agent Loop 只依赖统一 `LlmProvider`，启动层通过下面的固定链路选择上游：

```text
Profile（数据）
  → Adapter Registry（协议插槽）
    → LlmProvider（God 内部统一契约）
      → Agent Loop / WAL / Runtime
```

同一种协议新增上游，只增加 Profile；新增协议时注册一个 Adapter。Agent Loop、工具循环、多 Agent、WAL 和恢复逻辑不需要跟随修改。

## 内置 Adapter

| Adapter | 上游协议 | 工具调用 | 公开推理摘要 | 托管联网搜索 | 典型上游 |
|---|---|---:|---:|---:|---|
| `openai-responses` | `/v1/responses` | 是 | 是 | 是 | OpenAI、LovBrowser Responses 网关 |
| `openai-compatible` | `/v1/chat/completions` | 是 | 否 | 否 | Gundam Bridge、LovBrowser Bridge、Ollama、OpenAI 兼容中转 |

能力以 Adapter 的真实协议为准。兼容插头不会伪造上游不存在的 Reasoning Summary 或 Web Search 事件。

## 零迁移兼容

没有设置 Profile 文件时，行为与原来一致：

- `OPENAI_API_KEY`
- `OPENAI_BASE_URL`
- `OPENAI_MODEL`

默认 Adapter 是 `openai-responses`，仍连接 LovBrowser Responses 网关。也可仅用环境变量快速切到兼容协议：

```powershell
$env:AGENT_LLM_ADAPTER = "openai-compatible"
$env:AGENT_LLM_API_KEY_REQUIRED = "false"
$env:OPENAI_BASE_URL = "http://127.0.0.1:11434/v1"
$env:OPENAI_MODEL = "llama3"
node bin/god-agent.js
```

## 多 Profile 配置

复制 `examples/llm-profiles.example.json` 到仓库外的本机配置目录，然后设置：

```powershell
$env:AGENT_LLM_PROFILES_PATH = "C:\path\to\llm-profiles.json"
$env:AGENT_LLM_PROFILE = "gundam"
node bin/god-agent.js
```

`AGENT_LLM_PROFILE` 优先于 JSON 中的 `activeProfile`。

旧环境入口还支持 `AGENT_LLM_API_KEY_ENV` 指定密钥变量名。显式 Profile 不会隐式继承全局 `OPENAI_API_KEY`：需要 Key 时必须声明 `apiKeyEnv`，无需 Key 时设置 `apiKeyRequired: false`。

Profile 字段：

- `id`：唯一插孔名。
- `adapter`：已注册 Adapter id。
- `model`：默认模型。
- `models`：可选的模型选择器清单。
- `baseUrl`：上游 `/v1` 地址；没写 `/v1` 时自动补齐。
- `apiKeyEnv`：保存密钥的环境变量名，不是密钥本身。
- `apiKeyRequired`：本地无密钥服务可设为 `false`。
- `options`：Adapter 专属配置。

内置 options：

- 两种 Adapter：`timeoutMs` 必须是正整数。
- `openai-responses`：`reasoningSummary` 可为 `auto/concise/detailed/none`；`reasoningEffort` 可为 `minimal/low/medium/high/xhigh/max/ultra`；`serviceTier` 为非空字符串；`includeReasoningEncryptedContent` 为布尔值；`webSearch` 可设 `false`，或用 `searchContextSize=low/medium/high`。
- `openai-compatible`：当前只使用 `timeoutMs`，不会发送 Responses 私有参数。

Profile JSON 不应包含 API Key、Token 或 Cookie。密钥只从 `apiKeyEnv` 指向的环境变量读取。

Profile 在 App Server 启动时选择。`runtime/select-model` 修改当前 App Server 进程的默认模型；已有 Thread 配置可继续覆盖该默认值，它不是“每个 Chat 自动绑定独立 Provider/Profile”的实现。

## 扩展新协议

实现 `ConfigurableLlmProvider` 后，向 `LlmProviderRegistry` 注册：

```ts
registry.register({
  id: "vendor-protocol",
  capabilities: {
    toolCalling: true,
    reasoningSummary: false,
    hostedWebSearch: false,
    previousResponseId: false,
  },
  create: (context) => new VendorProvider(context),
});
```

随后 Profile 使用 `"adapter": "vendor-protocol"` 即可。WAL 会用 `adapter:profile` 记录供应商身份，避免不同插孔的调用审计混在一起。
