## 二、科研证据闭环：69% → 90%+，目标 95%

### E1：正式实验

产出真实 Provider 授权与调用记录、冻结的正式 Raw 数据、实验日志、时间戳、候选 SHA，以及失败和负结果记录。验收时必须证明调用真实发生、Raw 可校验、日志与候选一致；离线 Mock/Fake 不得替代正式实验。

### E2：Artifact 链

建立并冻结以下哈希链：

```text
Raw → derived → statistics → tables/figures → manuscript
```

每一环必须有 Manifest、SHA-256、生成 receipt、候选版本、采样时间和反向定位。

### E3：外部 baseline

使用公开数据集或公开基准，明确 comparator、资源约束、版本、许可和原始结果。不得用本机 Mock/Fake、同作者自制对照、文档描述、local pilot 或同作者同机器复跑冒充外部 baseline。

### E4：独立复现

由第二台机器、隔离环境或非作者执行者完成复跑，保留独立日志、receipt、结果差异和失败记录。独立复现必须能够与正式实验候选和 Artifact 对照。

### E5：证据审计收口

逐条闭合：

```text
Claim → Evidence → Artifact → Locator → Reviewer → Status
```

90% 门槛：正式 Raw、真实 Provider、外部 baseline、独立复现和主要 Claim 绑定全部完成；未完成项继续标记 `NotVerified/TODO`。  
95% 门槛：完成第二次独立复跑、负结果和限制记录、非作者复核，且候选、采样时间、Artifact SHA 和全部 evidence/release 门禁一致。

## 三、论文就绪度：47% → 90%+，目标 95%

### P1：冻结论文候选

固定论文候选、Artifact Manifest、结果快照、采样时间和候选 SHA。在工程覆盖和证据门槛达标前，不标记为最终版本。

### P2：补齐正式结果

将正式 Raw、统计结果、表格、图和正文数字绑定到同一 Artifact 链；未完成结果保留 `NotVerified/TODO`，不得把 Mock、Fake 或 local pilot 写成正式实验结果。

### P3：引用审阅

每条关键引用必须有稳定 ID、一手来源、版本或年份、HTTPS/DOI 定位、页码/章节/段落和审阅状态。

### P4：非作者论文级审阅

至少一名非作者审阅者逐 Claim 审阅方法、统计、威胁有效性、限制、负结果和引用，保留审阅意见、时间戳、审阅者身份和修订前后差异。

90% 门槛：正式结果替换主要 TODO，正文/表格/图与 Artifact 一致，核心引用核验完成，至少一次非作者审阅完成，paper/evidence 专项门禁通过。  
95% 门槛：非作者复核签字完成，结果/引用/限制/威胁有效性闭环，论文包可在干净目录复现，且不存在旧覆盖数字或旧候选漂移。

## 四、生产发行成熟度：68% → 90%+，目标 95%

### R1：依赖风险处理

对当前 3 个 high 采取依赖升级、补丁、替代方案或正式风险接受。未获得修改依赖和 `package-lock.json` 的授权前，继续保持 `BLOCKED`。

### R2：正式发行物

生成可安装包、签名信息、版本与候选绑定记录、SBOM、安全扫描报告、构建日志和 SHA-256 摘要。

### R3：干净 Windows 验证

在无开发依赖、无本机缓存的干净 Windows 环境验证安装、首次启动、Electron main/App Server/Renderer 联通、基础任务、卸载和错误恢复。

### R4：升级与回滚

验证 N → N+1 升级、配置和 Runtime state 迁移、升级失败恢复、N+1 → N 回滚及回滚后数据完整性。

### R5：长稳与恢复

固定时长运行并记录崩溃、内存增长、子进程退出、任务恢复、lease 超时、迟到响应、日志和恢复 receipt。

90% 门槛：3 个 high 已解决或有正式风险接受，签名安装包存在，干净 Windows 安装、升级、回滚和至少一次长稳运行通过，且 release/security/SBOM/doctor/Electron 门禁通过。  
95% 门槛：第二台干净机器复测，独立执行者完成安装和升级，长稳测试重复一次，安装包/SBOM/日志/候选 SHA 一致，发布审批和回滚预案完成非作者复核。

## 十一、证据状态机和禁止越界

```text
Draft/NotRun
  ↓ 有真实原始记录
Observed
  ↓ Artifact、receipt、候选和定位一致
Reproducible
  ↓ 独立环境或非作者复核
Reviewed
  ↓ 主控串行收口且所有门禁通过
Verified（仅适用于有充分证据的 Claim）
```

以下任一情况都必须回退并保持 No-Go：

- 只有文档、评分、Mock、Fake、Draft 或 local pilot；
- 只有同作者同机器复跑；
- 缺少正式 Raw、真实 Provider、外部 baseline 或独立复现；
- Claim、Artifact、候选 SHA、采样时间或 receipt 漂移；
- 覆盖分母或阈值变化；
- `evidence:verify` 或 `release:check` 阻断；
- 依赖 high 未解决且没有正式风险接受；
- 论文或发行材料把本地 ready 写成正式/生产 Verified。

### 3. 工程覆盖阶段的具体动作

1. 读取 coverage 未覆盖行报告，按真实可执行收益排序，不凭测试数量选题。

3. 每个切片只改互不重叠的测试范围；不修改依赖、快照、阈值、分母或 Claim 状态。
4. 每个切片固定执行：

   ```text

   npm run check
   npm run test:discovery
   npm test
   npm run test:coverage
   npm run test:coverage
   ```

5. 两次 coverage 不同时达到 95%，该切片只能记为 `RETURN_FOR_REWORK`，不得更新统一快照。
6. 覆盖率连续两次无有效增长、同一阻塞两轮不减少或命令结果完全相同时，停止重复操作并改策略。

### 4. 外部证据阶段的具体动作

1. 外部责任人提供真实 Provider 身份、调用授权、请求/响应 receipt、正式 Raw、失败和负结果。

3. 由第二机器、隔离环境或非作者完成独立复现，保存独立日志和差异。
4. 形成 `Raw → derived → statistics → tables/figures → manuscript` 的 Manifest/SHA/定位链。
5. 证据完整前，必须保持：

   ```text
   formalVerified=0
   formal Raw=NotIncluded
   real Provider=0
   external baseline=0
   independent reproduction=0
   publication review=NotReviewed
   ```
