## 4. P0 / P1 补足计划

### P0：全 `src` 覆盖达到 95

最低数学目标是 27,239/28,672，当前仍差 **800 行**。按风险和可覆盖收益依次推进：

1. `src/app-server/main.ts`：启动恢复、终态 Job 收口、可选模型/Skill、协议异常与进程关闭；
2. `src/cli/main.ts`：交互输入、权限拒绝、异常输出、恢复与退出路径；
3. Runtime Store/lease/lifecycle：坏快照、租约竞争、重启中断和 receipt 已提交后的保存失败；
4. MCP 与命令工具：启动失败、部分连接、关闭异常、拒绝与非零退出；
5. 每增加一组真实行为测试，执行专项、`npm run check`、正式 coverage；禁止空 import、排除文件、删除类型行或降阈值。

完成门：同一候选连续两次正式 coverage 均不低于 95.00%，且 summary 可解析、分母不回退。

### P0：外部复现证据

在候选提交冻结后补齐同 SHA 的远端 CI、干净 Windows 和第二台机器原始日志。任何未实际运行的模板、截图、Mock 或文字声明都记为“缺证据”，不得记为通过。

### P1：分支门与工程口径

- 建立关键 Runtime/权限/恢复模块的加权 branch gate；当前 loaded-file mean 不能冒充全仓加权分支覆盖；
- 将 type-only 文件从“运行覆盖”和“类型契约完整性”两个口径分别报告，但在既定 95 物理行目标未变更前，不用改口径宣布达标；
- 在具备符号链接权限的 Windows 环境消除条件 skip，并纳入同 SHA 证据包。

## 5. 最终判断

God-Agent 的 Runtime 闭环已经具备较强的正确性、恢复和 fail-closed 证据，V2/V3 关键协调器与 Return 恢复模块已达到或超过 95。当前最大短板不是演示文案，而是全 `src` 正式加权覆盖和外部复现：前者仍差 **800 行**，后者没有可采信的同 SHA 证据。

因此当前不能对考研复试声称“各工程环节均达到 95+”。准确说法应是：**关键 Runtime 闭环已达 95 级证据，全仓工程完整度 93/100，正式源码覆盖 92.21%，正在按 P0 清单持续补足。**
