## 2. 当前已经真实完成

- 复试定位已收敛为“长程任务可靠性研究原型”，没有把测试通过数换算成可靠性概率；
- GATE-40 可诚实表述为 candidate 40、local pilot 40 passed、formal Verified 0；
- Provider 保持离线确定性 Fake，`liveCalls=0`；
- 发布门禁会因 3 个 High 依赖风险失败关闭，production 仍 blocked；
- 7 页展示材料及独立 notes QA 已存在；
- Electron 项目重新构建通过，实际启动日志显示 runtime state restored、17 skills loaded、app-server ready、客户端初始化完成；
- 彩排证据协议已明显加固：7/7 定向测试与 TypeScript 检查通过，能拒绝重复证据、作者字段冒充、1 秒试讲、候选漂移和未来记录。

## 3. 为什么仍不能给 95

### P0：必须有真人才能关闭

1. 三次完整计时彩排尚未执行，当前 0/3；
2. 一次非作者试讲尚未执行，当前 0/1；
3. 没有可核验观察者对三次 timed 的现场确认；
4. 没有真实非作者确认“仅凭冻结材料、作者无实质介入”；
5. 没有压力追问、异常降级和问题复验形成的真实闭环。

### P0：项目事实门仍阻塞

1. 正式科研实验为 0，不能回答“论文结果已验证”；
2. live Provider 调用为 0，不能回答“真实模型链路已验证”；
3. 依赖审计有 3 个 High，production release 为 BLOCKED；
4. 没有第二机器或第二执行者独立复现；
5. 最新候选仍是未提交本地工作树，`remoteVerified=false`，不能称远端冻结版本。

### P1：本地仍可继续加固

1. timed 记录应同样强制 participant 与 observer 不同；
2. JSON Schema 应与运行时的“两类 Artifact + Passed 条件”完全对齐；
3. recording 应绑定 nonce、候选、开始/结束与净时长，而非只要求非空；
4. 生成冻结 rehearsal Manifest，并让讲稿、PPT、数字总账只消费该 Manifest；
5. 准备断网、无 Key、依赖异常三条 20 秒降级录像/截图及摘要。

## 4. 达到 95 的具体执行方案

| 顺序 | 行动 | 验收证据 | 预期影响 |
|---|---|---|---|
| 1 | 冻结一次候选与复试材料清单 | candidate digest、材料 digest、离线包摘要一致 | 防止彩排后材料漂移 |
| 2 | 完成三次 165–190 秒计时彩排 | 三组独立 nonce、录制、观察者确认、问题清单和复验摘要 | 关闭 timed 0/3 |
| 3 | 完成一次真实非作者试讲 | 身份/关系说明、无介入确认、录制、至少一条反馈闭环 | 关闭 non-author 0/1 |
| 4 | 做三类异常降级演练 | 断网、无 Key、依赖异常均在 20 秒内切换冻结证据 | 提升现场稳定性 |
| 5 | 做 10 分钟压力追问 | 至少 5 问，无提示回答；错误全部复验 | 提升答辩可信度 |
| 6 | 总控重新验证冻结证据包 | evidence verifier 通过 + 人工身份门签字 | 才允许复试分升到 95 |

其中第 2、3、5 项必须真实发生，不能由生成 JSON、复制文件或作者自签替代。

## 5. 当前可用的复试口径

建议说：

> God-Agent 是一个可运行、可测试、边界明确的多 Agent 长程任务可靠性研究原型。当前本机工程证据较强，GATE-40 已完成 40/40 local pilot，但 formal Verified 仍为 0；Provider 仍是离线 Fake，真实调用为 0；生产发布因 3 个 High 依赖风险保持阻塞。我会展示已经验证的机制，同时明确哪些仍是正式实验、外部基线和独立复现的下一步。

禁止说：

- “已经达到科研或生产 95+”；
- “40/40 证明可靠性 100%”；
- “真实 Provider 已验证”；
- “彩排已通过”；
- “依赖和发布已经安全”。

## 6. 最终裁决

当前项目**适合参加复试并作为强工程研究原型展示**，但按 95 合取门仍是 **90/100、No-Go**。最大缺口不是再写一份材料，而是完成真实的 3+1 彩排、压力追问、异常降级与独立观察证据。协议加固提升了防伪能力，不能把尚未发生的真人闭环变成已完成。

## 7. 第三波：可复验离线答辩冻结包

本轮新增 `scripts/offline-defense-bundle.ts`，将离线降级材料从“文件散落在工作区”提升为“候选与摘要绑定的冻结包”。它支持独立的 `create` 与 `verify`，并失败关闭以下情况：

- 输出目录已存在，拒绝静默覆盖；
- 必需的 evidence、PPT、PPT 检查报告、讲稿、问答、截图或报告缺失；
- 包内副本被删改、工作区源文件被删改、字节数或 SHA-256 漂移；
- Manifest 混入额外文件、重复路径、绝对路径、`..` 路径或非规范路径；
- 文本材料出现高置信 private key、OpenAI/GitHub/AWS 凭据模式；
- 讲稿、问答或 PPT 检查报告缺少当前统一 evidence 快照的权威数字；
- candidateRef、evidence 摘要、彩排状态、formal、live Provider 或 release 边界不一致。

### 对评分的影响

该能力把“离线降级材料准备度”从计划状态提升为**本机可复验完成**，现场断网或无 Key 时已有可信的只读材料集合。但它不证明：

- 冻结包已在真实复试设备打开；
- 20 秒内切换降级轨道的真人演练已完成；
- PPT 讲解、追问或非作者试讲已经发生；
- 当前未提交候选已经远端冻结。

因此它提升的是复试 90 分内部的离线交付质量，**不单独把整体分数提升到 95**。后续 evidence 或任一源材料发生变化时，现有包应按设计验证失败，必须用新候选重新生成，不能继续引用旧 Manifest 摘要。
